FAQ


      

        Do my files really stay on my computer?
        
Yes. BalanceProof is a static web app: the PDF is read and parsed by JavaScript running in your browser tab. There is no server to upload to. You can confirm this yourself: open your browser DevTools → Network tab, convert a statement, and you will see zero requests carrying file data. After the page loads, you can even go offline and keep converting.

      


      

        Which banks are supported?
        
BalanceProof uses layout-agnostic parsing tuned for common US (MM/DD/YYYY) and UK (DD/MM/YYYY) statement layouts, including card statements without a running balance. If your statement has a running-balance column, every parsed row is mathematically re-checked, so you know immediately whether it read correctly. Unrecognized lines are always shown so nothing is silently dropped.

      


      

        My PDF is a scan / photo. Does it work?
        
No — scanned statements are images and contain no text to extract. BalanceProof deliberately does not send your documents to an OCR cloud. Print-quality text PDFs downloaded from online banking work.

      


      

        How do I import into QuickBooks or Xero?
        
QuickBooks Desktop: export .qbo, then File → Import → Bank transactions; QuickBooks will ask you to map it to your account the first time. QuickBooks Online: use the Pro "QuickBooks CSV" export and import via Banking → File upload. Xero: use the Pro Xero CSV and import via Accounting → Bank accounts → Import a statement.

      


      

        Why does it sometimes flag rows as not reconciling?
        
Some banks print debits as plain positive numbers; BalanceProof auto-detects this, but unusual layouts can still slip through. Other causes: two-character OCR-style typos in the PDF text layer, or transactions that continue on the next page. The flagged rows are highlighted so you can fix or delete them before exporting.
